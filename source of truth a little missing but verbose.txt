IMPLEMENTATION / ARCHITECTURE FINDINGS FROM CODEBASE INSPECTION

This section records what was found by inspecting the actual SkyrimNet, IntelEngine, and existing IntelEngine addon code. These findings should be treated as implementation guidance for SkyrimNet-PersonalityUpgrade.

1. ADDITIVE PSYCHOLOGY PROMPTS VS CORE SKYRIMNET PROMPTS

SkyrimNet already has a broad roleplay instruction that tells the model to embody the NPC using background, personality, goals, relationships, speech style, emotional state, and related context, and to react authentically.

That instruction is shallow in the sense that it does not define the psychological process by which those inputs become a reaction, but it is not inherently incompatible with this mod.

Therefore the PersonalityUpgrade should NOT replace compatible broad SkyrimNet roleplay guidance simply because it is less detailed.

Instead, the additive psychology module should define what "react authentically" means:

- do not map events directly to emotion labels;
- interpret events from this specific character's subjective perspective;
- compare what happened with what they expected;
- infer what the event suggests about the other person, themselves, and the relationship;
- allow memories, values, insecurities, attachment patterns, pride, expectations, and current motives to affect appraisal;
- allow mixed or conflicting feelings;
- let conclusions affect future behavior indirectly as well as explicitly;
- preserve psychological continuity until later evidence gives a credible reason for revision;
- do not optimize for agreement or disagreement; optimize for psychological continuity.

SkyrimNet core guidance answers: WHAT information should influence the NPC?
PersonalityUpgrade answers: HOW should that information become a psychologically coherent reaction?

This is complementary and should be additive.

However, additive guidance is NOT sufficient when an upstream prompt explicitly violates the design. If an upstream prompt directly assigns a hidden motive, moral interpretation, or psychological conclusion as objective fact, then the conflicting prompt should be selectively overridden.

Implementation rule:

- Use additive prompt submodules when upstream is compatible but underspecified.
- Use targeted prompt overrides when upstream explicitly creates contradictory semantics.
- Avoid replacing large upstream prompts merely to make wording better if the existing behavior is already compatible.

This keeps the mod small and update-friendly while preventing contradictory instructions.

2. SKYRIMNET PROMPT EXTENSION MECHANISM

SkyrimNet's modding documentation explicitly supports numbered prompt submodules. Numeric prefixes determine ordering, and mod-integration ranges are provided for addon content.

This means the core psychological rules can be added as independent guideline submodules rather than by replacing SkyrimNet's main dialogue/thought prompts.

A likely structure is:

SKSE/Plugins/SkyrimNet/prompts/submodules/guidelines/0600_psychological_realism.prompt
SKSE/Plugins/SkyrimNet/prompts/submodules/guidelines/0610_epistemic_boundaries.prompt

Exact numbering should be chosen to load after SkyrimNet's general roleplay guidance.

The intended sequence is:

SkyrimNet: be this character; personality/history/goals/relationships matter.
PersonalityUpgrade: define how those things are psychologically interpreted and how private knowledge is separated from observable evidence.

3. SELF VS OTHER-CHARACTER INFORMATION IS ALREADY SUPPORTED

SkyrimNet already renders the active NPC using a full/self-facing character profile while rendering conversation targets with a dialogue_target mode.

The explicit personality/psychology block is already restricted to self-facing modes rather than being directly exposed to dialogue targets.

This architecture matches the mod's intended rule:

- an NPC's own generation can know its real personality and private internal material;
- another NPC should not automatically receive that private personality as objective truth;
- observers should infer personality from observable behavior, remembered interactions, reputation, hearsay, and their own interpretations.

The mod should strengthen this boundary, not rebuild it.

4. PUBLIC CHARACTER SUMMARY IS A POTENTIAL LEAKAGE POINT

SkyrimNet's public summary is rendered in several modes, including dialogue-target and short-inline contexts.

SkyrimNet's dynamic bio system already contains a strong Stranger Test: public summary/appearance information should contain only what a stranger could observe or know through public reputation. Private thoughts, hidden motivations, secret backstory, and insider knowledge should not belong there.

This is compatible with PersonalityUpgrade, but actual static or generated content can still violate that ideal.

Therefore the mod should treat public summaries as evidence/reputation, not as privileged access to another person's hidden mind.

Rule: A public summary may inform what an observer has plausibly heard or can perceive, but psychological claims about another character must not automatically become guaranteed inner truth unless the observer has legitimate knowledge of them.

5. PLAYER HAS NO CANONICAL PERSONALITY SHEET

SkyrimNet can render the player through profile/short-inline paths in some prompts. The underlying framework therefore supports player-profile information.

For this mod's intended game setup, that information must not be treated as a canonical inner personality for the player. The player is the user, not an AI-authored character sheet.

NPCs should form models of the player from:
- what the player actually says;
- what they personally hear;
- what they personally witness the player doing;
- consequences of the player's actions;
- promises kept or broken;
- repeated behavioral patterns;
- public reputation where appropriate;
- credible information communicated by others;
- the NPC's own memories and interpretations.

No generated/configured player personality description should override those observations as the player's true inner self.

6. MEMORY SYSTEM: SUBJECTIVITY IS CORRECT, BUT EMOTION MUST BE DOWNSTREAM

SkyrimNet's memory pipeline uses emotional-impact / mood information and generates first-person memories for an individual NPC.

Subjective memories are desirable. NPC memories SHOULD contain personal interpretation, because they belong to that NPC.

The important distinction is:

World event: neutral/perceptible description of what happened.
NPC memory: what this particular NPC believes, felt, learned, or now expects because of it.

The emotion label must be treated as an outcome of appraisal, not as a shortcut that dictates the appraisal.

Bad conceptual pipeline:
event -> predefined emotion -> memory interpretation

Desired pipeline:
event -> character-specific appraisal -> meaning -> mixed feelings/motives -> closest supported emotion metadata/tag

The existing SkyrimNet emotion field can remain for structural compatibility. PersonalityUpgrade should change how the model arrives at it.

7. PRIVATE THOUGHTS ARE THE RIGHT LOCATION FOR DEEP APPRAISAL

SkyrimNet already treats NPC thoughts as private cognition that is not heard by other characters and is stored in that NPC's own history.

Therefore private thought generation is the ideal place for rich internal appraisal.

The appraisal questions are reasoning principles, NOT an output template. NPC thoughts should still sound like the character, not like a psychology worksheet.

Bad: "Relationship implication: trust has decreased."
Good: "I handed him something private and he passed it on like it meant nothing. I won't make that mistake twice."

8. CORE INFORMATION HIERARCHY

The system should distinguish at least four levels:

A. Objective / externally recordable event
Example: "She looked away when he spoke."

B. Perceptible affect
Example: "She appeared nervous and repeatedly looked away."

C. Observer interpretation
Example: "She must be intimidated by him."

D. Deeper psychological theory
Example: "Authority figures make her insecure because she fears humiliation."

A and B can legitimately appear in external/perceptual context when supported by what can be observed. C and D belong to a character's own reasoning unless explicitly spoken, credibly communicated, or otherwise made knowable.

Perceptible emotional state is NOT the same thing as forbidden mind-reading. Visible nervousness, anger, fear, amusement, intoxication, exhaustion, etc. can be valid observations when perceptible.

The forbidden leap is from perceptible evidence to asserted hidden cause, moral judgment, enduring trait, or relationship meaning.

9. PRIVATE CAUSE MAY DRIVE SIMULATION WITHOUT BECOMING PUBLIC DESCRIPTION

This is a central architectural rule:

PRIVATE PSYCHOLOGICAL STATE MAY DETERMINE WHAT A CHARACTER DOES, BUT IT MUST NOT AUTOMATICALLY BECOME PART OF THE OBSERVABLE DESCRIPTION OF WHAT THEY DID.

Example:
Private cause: "She follows the player because she is jealous."
Valid world event: "She followed the player from the inn to the city gate and hid when they turned around."

Possible observer interpretations:
"She's jealous."
"Maybe she suspects them of something."
"That's unsettling."

Her own private thought may know the true motive if appropriate.

This principle applies to jealousy, fear, pride, resentment, attraction, suspicion, insecurity, loyalty, revenge, embarrassment, and similar hidden states.

10. INTELENGINE STORY DM: CONFIRMED HIDDEN-MOTIVE LEAK

Inspection of IntelEngine's intel_story_dm.prompt found an explicit example equivalent to:
"was caught following the player out of jealousy"

This violates the mod's source-of-truth design because "out of jealousy" exposes a hidden causal interpretation in world narration.

The event system may use jealousy in private state/memories to decide that this NPC is a plausible follower. That is acceptable.

What should be stored externally is the observable event, for example:
"was caught following the player outside Whiterun"

Optionally with perceptible behavior:
"appeared flustered when confronted and fled"

but not the hidden causal explanation unless that motive was explicitly revealed.

Therefore intel_story_dm.prompt is a strong candidate for a TARGETED OVERRIDE rather than relying only on additive global guidance.

11. INTELENGINE NPC-TO-NPC STORY DM

intel_story_npc_dm.prompt is structurally closer to the desired model. Its generated facts often record concrete actions such as confronting someone about stolen goods or being accused of theft.

It also has per-NPC knowledge isolation: one NPC may know a fact another NPC does not, and information can propagate through communication.

This is highly compatible with PersonalityUpgrade.

However, categories such as betrayal, romantic tension, shared grudges, etc. may be used internally when selecting interesting interactions. That is acceptable as simulation metadata, but those labels should not automatically become objective persistent facts.

Gossip requires special care.

If Aela says:
"Vignar ran because he's a coward."

Ria should not receive the objective fact:
"Vignar is a coward."

A correctly attributed record is closer to:
"Aela told Ria that she believed Vignar fled out of cowardice."

Then Ria can accept, reject, reinterpret, or remain uncertain about Aela's claim according to her own psychology and knowledge.

Therefore intel_story_npc_dm.prompt is also a likely targeted override, but the required changes are narrower than the Story DM changes.

12. INTELENGINE POLITICAL DM

intel_political_dm.prompt mostly produces concrete political/world events and is closer to acceptable neutral narration than Story DM.

It can use leader personality and relationships internally to determine what a leader/faction chooses. This is legitimate for an omniscient simulation engine.

Again, the resulting public event should describe what occurred rather than automatically expose the hidden reason.

Example:
Private simulation reason: A cautious leader avoids escalation.
Public event: "Whiterun rejected immediate military action and requested further negotiations."
Not automatically: "Balgruuf rejected the proposal because his cautious personality made him fear escalation."

Political mechanics may retain internal event-type labels such as betrayal if required for engine behavior. The natural-language world record should still state the underlying action neutrally, such as breaking an agreement, rather than force an observer's moral interpretation.

13. WORLD_KNOWLEDGE MUST BE ESPECIALLY STRICT

IntelEngine political/world knowledge can be treated as authoritative truth by downstream systems.

Therefore subjective wording in world_knowledge is especially dangerous because it can become canonical for every later observer.

Bad authoritative fact:
"Ulfric cowardly abandoned his troops."

Better:
"Ulfric left the battlefield while Stormcloak forces remained engaged."

If another character publicly judged the event, attribution can preserve that safely:
"Galmar publicly accused Ulfric of cowardice after Ulfric left the battlefield."

The judgment is now an objective fact about Galmar's statement, not objective truth about Ulfric's psychology or character.

14. NATURAL CONVERGENCE IS ALLOWED

The mod must NOT instruct NPCs to disagree for variety.

Different NPCs may independently reach the same interpretation when evidence strongly supports it.

Several NPCs may all decide that an event was embarrassing, suspicious, impressive, or cruel.

What should remain individualized is the path, meaning, intensity, emotional mixture, and downstream behavior.

Interpretation convergence is not the same as psychological convergence.

Example: several NPCs may all think "that was embarrassing," while one loses attraction, one feels sympathy, one finds it endearing, one experiences second-hand embarrassment, and another respects how calmly the person recovered.

15. OBSERVABLE REACTIONS OF OTHER PEOPLE ARE EVIDENCE

Social consensus can affect later interpretation, but it should do so through observable reactions rather than omniscient narration.

Good event record:
"Three guards laughed after he fell. One person looked away. The Thane paused before continuing."

Bad event record:
"Everyone found the incident humiliating."

An NPC can observe the laughter and independently decide that the social meaning is worse than they initially thought.

16. EXISTING ADDON PACKAGING PATTERN

IntelEngine-EmergentNPCConversations was inspected as a working addon example.

It ships SkyrimNet prompt overrides using the same relative game path, for example:
SKSE/Plugins/SkyrimNet/prompts/intel_story_npc_dm.prompt

Its release directory mirrors that structure.

This confirms that PersonalityUpgrade can selectively replace a named IntelEngine/SkyrimNet prompt by shipping the same relative path rather than editing the upstream repository directly.

The addon also demonstrates a separate Papyrus override workflow: upstream sources are copied into an isolated build area, a specific source file is replaced, and the result is compiled.

At present, no Papyrus change has been demonstrated as necessary for PersonalityUpgrade V1. The current design appears achievable primarily through prompt additions and targeted prompt overrides.

18. IMPLEMENTATION PRIORITY

The V1 implementation should prefer:

1. Additive psychological-realism guideline.
2. Additive epistemic/privacy boundary guideline.
3. Explicit player-no-canonical-personality rule.
4. Targeted IntelEngine Story DM neutrality fix.
5. Targeted NPC-to-NPC fact/gossip attribution fix.
6. Test behavior before overriding additional large prompts.

The intended result is not a scripted relationship system. It is a stricter information architecture plus a deeper psychological reasoning policy layered onto SkyrimNet/IntelEngine's existing systems.

The central design principle remains:
Do not merely identify an emotion. Simulate the subjective meaning that produced it.

The central information principle is:
Let hidden psychology influence behavior without automatically leaking that hidden psychology into the shared description of behavior.
